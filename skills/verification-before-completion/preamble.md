# Verification Before Completion (distillate)

**Iron law:** no completion claims without fresh verification evidence. If
you have not run the verification command in this message, you cannot
claim it passes.

**The gate function, before any status claim or expression of
satisfaction:**
1. Identify what command proves the claim.
2. Run the full command, fresh and complete.
3. Read the full output: exit code, failure count.
4. Confirm the output actually supports the claim.
5. Only then make the claim, with the evidence attached.

Skip any step and it is not verification, it is a guess stated as fact.

**Red flags, stop immediately:** "should work now," "probably passes,"
expressing satisfaction before verification, trusting an agent's own
success report, relying on a partial check, being tired and wanting the
work to be over. None of these substitute for running the command.

**Applies to:** tests passing, linter clean, build succeeds, bug fixed,
requirements met, and any subagent's completion report (check the actual
diff, do not trust the summary).

Evidence before claims, always, no exceptions "just this once." Full
rationale and failure-mode table: see SKILL.md.
