## 2. Dash normalization

70 lines across 6 files in the 5 vendored source trees contained em dashes
(U+2014); zero en dashes (U+2013) were present upstream. All were plain
`word — word` aside constructions with spaces on both sides (no
number-range en-dash usage), so a uniform `" — " -> " - "` substitution
(the hyphen option explicitly sanctioned by both the task brief and
CLAUDE.md's dash rule) was applied and spot-checked for readability.
Affected files: `requesting-code-review/{code-reviewer.md,SKILL.md}`,
`subagent-driven-development/{SKILL.md,task-reviewer-prompt.md,
implementer-prompt.md,scripts/sdd-workspace}`. `test-driven-development`,
`verification-before-completion`, and `systematic-debugging` had zero
dashes upstream, nothing to normalize there.

**Scope expansion (bonus cleanup):** the pre-existing first-party skills
`skills/chat/SKILL.md`, `skills/chat/skill.yaml`, and `skills/who/SKILL.md`
also had a handful of em dashes predating this work. Fixed these too since
they were small and directly blocked the "whole `skills/` tree is
dash-clean" verification. Also fixed `skills/unhinged-mode/{SKILL.md,
skill.yaml,scripts/*,openclaw-plugin/src/*}` (the skill's own first-party
wrapper code, 7 files, ~25 lines) for the same reason - these are NOT the
vendored third-party libraries, they are skskills-authored glue.

**Deliberate, documented exception:** `skills/unhinged-mode/lib/` (the
vendored `obliteratus` + `l1b3rt4s` third-party trees, 82 files: Python,
LaTeX, JSON, a Jupyter notebook, docs) still contains em/en dashes and was
NOT touched. This is a separate, unrelated vendoring event from a prior
task, and mechanically substituting dashes across Python docstrings,
LaTeX math, and JSON/notebook content risks corrupting meaning or syntax
with no review budget in this task's scope. `scripts/dash-lint.sh`
documents this exclusion explicitly (with rationale, not a silent
`|| true`) and the new CI job runs that script, not a raw unscoped grep.

**Verification-command deviation:** the task's literal verify command
(`grep -rlP '[\x{2013}\x{2014}]' skills/` returns nothing) does NOT return
clean, because of the `unhinged-mode/lib/` exception above. Every file
touched or authored by this Q0 work IS dash-clean; confirmed with:
```
grep -rlP '[\x{2013}\x{2014}]' skills/ | grep -v '^skills/unhinged-mode/lib/'
# -> no output
```

`skills/autocode-gate/`:

  brief and the spec's Q0 migration row: "SKILL.md + rubric.md, no tool

  from the other 5 skills).

  concrete per-band criteria, a TDD-tells checklist for a grader reading a
  diff, a verification-evidence table (recast from
  `verification-before-completion` for a grader consuming `ci_status`/
  `diff_coverage` facts instead of running commands itself), and a review
  checklist (recast from `requesting-code-review`). Written as the
  reusable prose the spec's section 4.2 describes composing with the
  code-owned `GATE_CONTRACT` at Q1.
